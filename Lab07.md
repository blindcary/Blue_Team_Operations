# Lab 03: Network Forensics with Wireshark

## Overview
In Lab 01 and 02, I established **detection** and **monitoring** using Suricata and the ELK Stack. In this lab, I shifted to **deep forensics** using Wireshark. While an IDS tells you *that* an attack happened, Wireshark allows you to capture the raw network packets to understand exactly *how* it happened and *what* data was exfiltrated. This layer of visibility is critical for defending physical server infrastructure.

## The Setup
* **Tool:** Wireshark v4.6.0 running on Kali Linux.
* **Interface:** Loopback (`lo`) to capture local attack simulations.
* **Objective:** Capture and analyze the traffic generated by the reverse shell and spoofed HTTP requests from previous labs.

## Analysis & Key Findings

### 1. Capturing the "DNA" of a Reverse Shell
I started a Wireshark capture on the `lo` interface and executed the Netcat reverse shell attack. By filtering the capture for `tcp.port == 4444`, I isolated the C2 (Command & Control) traffic.

Using the "Follow TCP Stream" feature, I reconstructed the entire session in plaintext, revealing the exact commands executed by the attacker.

### 2. Identifying Malicious HTTP Headers
I also captured the `curl` attack using the spoofed `"Trusted-Update-Service"` User-Agent. By filtering for `http`, I could inspect the full HTTP header stack. This confirmed that while the request looked legitimate on the surface, the packet headers contained the malicious signature that triggered our Suricata rules.

## Physical Server Security Implications
Moving from cloud to physical servers requires a deeper understanding of the OSI model. Wireshark provides visibility down to Layer 2 (Data Link), which is essential for physical environments to detect:
* **ARP Spoofing/Poisoning:** Attackers redirecting traffic on the physical switch.
* **Rogue Devices:** Unauthorized hardware plugged into physical Ethernet ports.
* **MAC Address Anomalies:** Identifying devices that shouldn't be on the local network segment.

## Conclusion
Mastering packet analysis allows me to move beyond relying solely on automated alerts. I can now validate false positives, perform in-depth incident response, and carve out malicious payloads directly from network traffic, a vital skill for securing bare-metal infrastructure.
